【一】这东西是干什么的
------------------------------------------------------------------------

一句话: 把"重装完系统之后要装的一堆软件"变成一张清单 + 一个启动器，
让用户自己决定装什么、装在哪里，一键装完，不联网也能用。

它不是一个"装机必备全家桶"。它解决的是这四件事:

  1. 清单化 —— 所有要装的软件集中登记，谁在哪个分类、从哪来、怎么装，
     全部写在 CSV / JSON 里，看得见、改得动、可以版本管理。
  2. 可决策 —— 启动器把清单摆出来，用户勾选。装什么、装到哪个盘、
     要不要打补丁，全部是用户点的，没有"偷偷装"。
  3. 不重复劳动 —— 检测本机已装情况，已装的默认不勾；重装系统后清单和
     安装包都还在（放在独立数据盘），不用从零再想一遍。
  4. 可扩展 —— 别人可以做一个插件文件，把自己下载的 / 自己做的应用
     塞进任一个分类，放进目录就生效。


【二】设计理念
------------------------------------------------------------------------

理念 1: 数据驱动，界面只做壳
    检测逻辑、安装逻辑、分类规则全部在 PowerShell 引擎里，界面（C# WPF）
    只负责"读状态、显示、把用户的选择传回引擎"。
    好处: 命令行和图形界面看到的结论永远一致，不会出现两套判断分叉；
    引擎可以在没有界面的机器上单独跑。

理念 2: 英文目录，路径可预期
    所有目标目录都是英文: E:\Apps\<英文分类>\<英文子目录>
    例: E:\Apps\Security\huorong 、E:\Apps\Modeling3D\Maya_2026.3
    中文名只用于显示。中文目录名在跨工具、跨脚本、跨压缩包时是灾难，
    所以从生成清单那一刻就把中文压成 ASCII，压不出来就退回用条目 id。

理念 3: 本地优先，云端补位
    找包的顺序是: 本地已有 → winget → 官网直链 → 云盘分享 → 手动提示。
    本地有包就绝不上网；能静默装就绝不弹窗口；只能人工点的就明确说"手动"，
    不猜、不硬来。

理念 4: 事实优先，成败以复检为准
    不看安装器退出码。winget 和各家安装器退出码含义不统一，实测出现过
    "返回 0 但没装上"和"返回奇怪负数但其实只是卸载旧版失败"。
    所以每次装完都重新检测一遍，复检说装上才算成功。

理念 5: 幂等
    重复运行只会补装缺失项，已经装好的跳过。随时可以中断、随时可以再来。

理念 6: 危险动作让人来做
    刷固件会变砖、网盘分享要登录、商业软件官网只有试用版 ——
    这些不包装成"一键"，而是明确告诉用户该干什么。
    程序不替用户做"看起来聪明但可能毁机器"的决定。

左侧导航就是软件分类目录树:

    全部软件                 所有分类的合集
    ├─ 安全清理   (2/23)     每个分类一个独立子页面
    ├─ 基础工具   (7/8)      括号 = (已装 / 总数)
    ├─ 聊天社交   (5/5)
    ├─ 网盘       (3/4)
    ├─ 下载       (5/9)
    ├─ 浏览器     (1/2)
    ├─ 网络加速   (3/4)
    ├─ 3D建模     (8/9)
    ├─ 外设软件   (0/10)
    ├─ 组件运行库 (69/69)
    └─ 你自己的插件分类
    ───────────────────
    运行库驱动 / 安全清理 / 硬件 / 网盘下载 / 日志

    分类子页面是按清单自动生成的 —— 新增分类或装了插件，导航自己多一项，
    界面代码不用改。

每个软件卡片写清三件事:
    - 名称 + 层级（核心 / 推荐 / 按需）
    - 会装到哪里: E:\Apps\<英文分类>\<英文子目录>
    - 从哪来: 本地安装包 / 123云盘 / 官网下载 / winget / 手动

筛选与操作:
    层级          核心 / 推荐 / 按需 三层可勾，默认只要 核心+推荐
    只看未安装    默认不勾（先看全量），勾上只剩缺失项
    全选/全不选   只作用于当前这一页
    安装勾选项    只装勾上的
    打补丁        只跑清单里标了「补丁程序」的项
    网盘下载并安装 先按登录态把云盘里的包批量拉下来，再自动装
    安装根目录   默认 E:\Apps，可改
    重读清单     改了 清单\*.csv 后重新汇总
    插件工作区   图形化做一个自己的插件

【六】它是怎么工作的
------------------------------------------------------------------------

── 6.1 数据流 ──────────────────────────────────────────────

    清单\*.csv（人维护）     插件\*.json（谁都能做）
          │                        │
          │                        └─(插件管理.ps1)→ 插件目录.csv
          │                                            用户分类.csv
          └──────────(生成目录.ps1)─────────────────────────┘
                              │
                              ▼
                     清单\软件目录.csv   ← 全量总表（同一份格式）
                              │
                    (导出状态.ps1 + SoftwareLibrary.ps1)
                      检测本机 + 定位本地包 + 决定落地方式
                              │
                              ▼
                  StatusSnapshot JSON ──→ 启动器界面（只读它）


── 6.2 启动器怎么拿到状态 ───────────────────────────────────

    启动器不自己检测。它调 引擎\导出状态.ps1，脚本返回一份 JSON:
      机器信息 / 运行库 / 3D / 安全清理 / 组件 / 硬件 / 驱动源 /
      外设 / 以及全量软件清单（每项带: 目标目录、来源、本地包是否就位、
      已装与否、依据）。
    界面把 JSON 反序列化后填控件。所以"命令行看到什么，界面就是什么"。

    另外: 界面启动时先用 -RuntimesOnly 快速模式（约 1~2 分钟），
    切到"运行库驱动/硬件"页时再跑完整硬件枚举和 Windows Update 驱动查询。

── 6.3 装一个软件时到底发生了什么 ──────────────────────────

    对每一个被勾选的条目，引擎按这个顺序决定怎么落地:

    ① 本地已经有包（E:\安全软件 / 缓存\安装包 / E:\Work）
         → 便携类: 7z 解压到目标目录（按"解出来的体积对不对"判断成败，
           不对就重试 3 次；解不出 exe 就把原文件直接复制进去）
         → 安装类: 跑安装器（.msi 走 msiexec /qn）
    ② 清单/插件给了 wingetId
         → winget install --id X --exact --silent（自动提权、自动写卸载项）
    ③ 有官方直链且能推出文件名
         → 自动下载到 缓存\安装包（带重试），再按 ① 装
    ④ 只有官网页面
         → 用浏览器打开，用户自己点
    ⑤ 只有云盘分享文件
         → 有登录态就自动批量下载，没有就打开分享页并把文件名列出来
    ⑥ 其它
         → 明确标"手动"，写清为什么

    装完: 重建桌面快捷方式 → 跑补丁（如 Bandizip 专业版补丁）→
          复检 → 写 报告\软件安装_*.csv

── 6.4 检测是怎么做的 ──────────────────────────────────────

    检测库（库\检测.ps1）只报事实，不敢下结论时说"未知"，绝不当成"缺失"
    （误报缺失会导致重复安装）。检测方式:
       arp        匹配"程序和功能"里的显示名或注册表键名（最常用）
       regRelease .NET Framework 的 Release 号
       regSubkey  JDK 这类按版本开子键的
       dotnet     dotnet --list-runtimes
       webview2   Edge WebView2
       file       DirectX 这类只落 DLL、不写注册表的
       msix       Appx / MSIX 包
       none       不做检测（工具类）
    检测结果有缓存（全量 140+ 项约 1~2 秒），但安装后复检前必须清缓存，
    否则复检读到的是安装前的快照。


【七】123 云盘集成
------------------------------------------------------------------------

── 7.1 为什么需要登录 ──────────────────────────────────────

    123 云盘的分享接口:
       列目录  不需要登录
       取直链  需要登录，未登录一律返回
               {"code":5112,"message":"您需要注册登录或付费后下载"}

    所以"打开分享页手动下载"是底线体验，登录后才能批量自动下载。

── 7.2 一键登录（推荐）────────────────────────────────────

    启动器 → 网盘下载 → 「用浏览器登录（推荐）」:
      1. 用本机 Edge/Chrome（Chromium 内核）以 --app 模式开一个窗口
      2. 同时开 CDP 调试端口，脚本轮询读 localStorage + cookie
      3. 把读到的候选凭据逐个拿去"真的取一次下载直链"
      4. 能用的那份写进 123云盘cookie.txt
      5. 关掉窗口即收尾
    窗口用独立配置目录（缓存\浏览器配置），不动日常浏览器数据。

── 7.3 手动兜底 ───────────────────────────────────────────

    浏览器登录 123pan.com → F12
      · Network → 任一 /api/ 请求 → 复制整条 Cookie
      · 或 Application → Local Storage → 复制 PassportToken / token
    粘进「网盘下载」页 → 保存并自检（自检会真的取一次直链验证）。

── 7.4 分享接口限频 ───────────────────────────────────────

    未登录时连续请求会被限:  "code=429 分享接口请求过于频繁"
    脚本做了候选去重 + 429 冷却 60 秒，不会把接口打爆。

── 7.5 下载落地 ───────────────────────────────────────────

    下载到 缓存\安装包\（独立于系统盘，重装后仍在）。
    第二次运行同一个清单，所有包都会"缓存命中"，不再联网。


【八】插件体系
------------------------------------------------------------------------

── 8.1 一个插件就是一个 JSON ──────────────────────────────

    放进 E:\安装系统\插件\ 就生效。启动器「软件清单」里立刻多出
    这些条目和分区。

── 8.2 插件工作区（图形化做插件）──────────────────────────

    启动器 → 全部软件/任一分类页 → 「插件工作区」:
      1. 填插件名 / 作者 / 插件 id（英文，就是文件名）/ 说明
      2. 选分类: 内置分类任选，或「新建分区」自己开一个
         （自定义分区会写出英文目录名，例: 我的工具 → MyTools）
      3. 逐个添加应用，每个应用选一种来源:
           123 云盘    分享链接 + 文件名（用你的登录态自动下载）
           官方链接    https:// 直链（自动下载再装）
           winget      包 ID
           本地文件    文件名（从 安全软件 / 缓存\安装包 / E:\Work 里找）
           只提示      只列出来，提示用户自己处理
      4. 点「生成插件」→ 写文件 → 自动重建索引 → 启动器自动重读清单
    还能「读入 JSON」继续编辑别人的插件，或「导出 JSON」发给别人。

── 8.3 插件文件格式 ───────────────────────────────────────

    {
      "schema": 1,
      "id": "derek-tools",
      "name": "小明常用工具",
      "author": "小明",
      "version": "1.0",
      "description": "自用便携小工具集合",
      "categories": [ { "name": "我的工具", "dir": "MyTools" } ],
      "apps": [
        {
          "name": "我的截图工具",
          "id": "myshot",
          "category": "我的工具",
          "sub": "MyShot",
          "tier": "推荐",
          "source": "pan123",
          "shareUrl": "https://<uid>.share.123pan.cn/123pan/<key>",
          "file": "我的截图工具.7z",
          "mode": "便携",
          "detect": { "method": "arp", "param": "MyShot" },
          "note": "自己打包的便携版"
        }
      ]
    }

    字段:
      source   pan123 | official | winget | local | manual
      mode     便携（解压）| 安装（跑安装器）| 手动
      tier     核心 | 推荐 | 按需
      detect   { method: none|arp|file|pnp, param: ... }
      dir/sub  会被强制压成纯 ASCII（目标目录里不能出现中文）
      silent   安装类的静默参数（可选）
      patch    解压后要跑的补丁（可选）

── 8.4 插件应用和内置条目完全同权 ─────────────────────────

    走同一套引擎: 同一个分类目录规则、同一个检测、同一个落地优先级。
    所以插件的应用一样能用云盘登录态、一样有缓存、一样会复检。
    插件里的东西不需要任何特殊处理。

── 8.5 目前只支持 123 云盘 ────────────────────────────────

    其它网盘以后加。加法是再写一个"分享解析"库（像 库\123云盘.ps1），
    其余全部不用动。


【九】命令行等价物（没有界面也能用）
------------------------------------------------------------------------

    # 汇总 清单\*.csv → 清单\软件目录.csv
    引擎\生成目录.ps1

    # 只看计划: 每项该走本地包 / winget / 官网 / 云盘 / 手动
    引擎\安装软件.ps1

    # 装指定分类（英文目录名），先按登录态批量下云盘
    引擎\安装软件.ps1 -Install -Yes -Category Security,BasicTools -Root E:\Apps

    # 只装指定项 / 只打补丁 / 不碰云盘
    引擎\安装软件.ps1 -Install -Yes -Only bandizip,everything
    引擎\安装软件.ps1 -Install -Yes -PatchOnly
    引擎\安装软件.ps1 -Install -Yes -NoCloudDownload

    # 运行库专用（直链 + SHA256 校验 + winget + 复检）
    引擎\系统安装.ps1 -Report        # 只看状态，不动系统
    引擎\系统安装.ps1 -Yes           # 装核心+推荐
    引擎\系统安装.ps1 -Tier 核心 -Yes

    # 驱动 / 安全清理
    引擎\驱动安装.ps1 -Yes
    引擎\安全清理.ps1 -Report

    # 插件
    引擎\插件管理.ps1                              # 列插件 + 校验 + 重建索引
    引擎\插件管理.ps1 -Validate .\插件\demo-tools.json
    引擎\插件管理.ps1 -New mytools -Name "我的工具"  # 生成骨架
    引擎\插件管理.ps1 -FromJson .\下载\mytools.json  # 工作区写盘走这条

    # 网盘登录态
    引擎\网盘登录.ps1                # 开 Chromium 窗口登录并自动取登录态
    引擎\网盘凭据.ps1 -Cookie '<cookie>'


【十】怎么维护清单

── 10.1 加一个软件（内置分类）─────────────────────────────

    在对应 清单\<分类>.csv 里加一行:
      Id            内部稳定标识（也是缓存文件名）
      名称          显示名
      类别          分组（用于显示）
      层级          核心 / 推荐 / 按需
      分享文件名    网盘里的文件名（本地导入时按它匹配）
      包文件名      本地包名（3D 类用）
      wingetId      winget 包 ID
      官网直链      官网地址
      安装方式      安装 / 便携 / 手动
      检测方式      见 6.4
      检测参数      见 6.4
      补丁程序      解压后要跑的补丁（可选）
      说明          备注

    加完跑:  引擎\生成目录.ps1  然后启动器「重读清单」。
    清单改完不用动任何代码和界面。

── 10.2 加一个分类 ────────────────────────────────────────

    在 清单\类别.csv 加一行:  类别,英文目录,清单文件
    然后在 清单\新建清单.csv 里填条目。导航会自动多一项。

    把 .json 丢进 插件\ 目录 → 启动器「重读清单」或跑 插件管理.ps1。


【十一】已知约束与坑（都踩过并绕开了）
------------------------------------------------------------------------

  · PowerShell 5.1 读含中文的脚本必须有 UTF-8 BOM，否则中文全乱码、
    脚本直接解析失败。引擎里所有 .ps1 都带 BOM。
  · 开关参数不能和同名变量冲突。曾经把 `-Plan` 开关和 `$plan` 变量
    写在一起，PowerShell 会持续把 ArrayList 往 SwitchParameter 上转，
    报错还指到不相干的代码行 —— 现在变量叫 $jobs。
  · Export-Csv 5.1 是拿"第一行"的列当表头的。往一个已有表头的数据里
    混入"多几列"的行，多出来的列会被整列丢掉。所以导出前显式 Select
    一次全部列。
  · 123 云盘分享接口有限频（429），脚本做了候选去重 + 60 秒冷却。
  · 单元素集合在 PowerShell 里会被自动"解包"成单个对象，`.Count` 变空。
    凡是返回可能只有一个元素的集合，都要 @(...) 包一层。
  · 7z 解压损坏的包时退出码不可靠（0/1/2 都可能），所以按"解出来的
    体积对不对得上压缩包"判断，不对就重试。
  · 刷 BIOS/EC 固件中途断电会变砖 —— 默认不装固件，要显式勾选。
  · 123 云盘的登录态（cookie/token）只存在本机 123云盘cookie.txt，
    只发往清单里登记的分享地址，不上传任何地方。

【十三】快速上手（三句话）
------------------------------------------------------------------------

  1. 装东西: 双击 SetupLauncher.exe → 左侧选分类 → 勾要装的 → 
     「安装勾选项」；缺包它会告诉你缺什么、去哪拿。

     「生成插件」，别人给你 json 丢进 插件\ 目录也一样生效。
